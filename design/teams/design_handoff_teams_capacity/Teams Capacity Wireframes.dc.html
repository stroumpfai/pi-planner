8bThe two dnd-kit interactions, spelled out
1 · Drag-to-create in the absence grid — custom, not Sortable
unit
one half-day cell = { memberId, date, half }; 8px wide, 15px tall, 1px gap
sensors
PointerSensor (activation distance 4px) + KeyboardSensor for the accessible path
drag
pointer-down on a cell sets the anchor; move extends a rectangular range over date × member rows; live count in an overlay chip (“12 half-days”)
drop
opens the Add-absence dialog (3a) pre-filled from the range — never writes silently
invalid
non-working halves and “not yet on team” cells are skipped, not blocked: the range clips, cursor stays valid
keyboard
arrows move the focused cell, Space anchors, Shift+arrows extend, Enter opens the dialog, Delete triggers the same confirm as the bin in the selected-entry bar
css
touch-none select-none on the grid; the minimap window is a separate draggable with the same sensor
2 · Reordering rows and columns — SortableContext
Members
vertical strategy, handle is the ⠿ grip only; order persists per team
Meetings
horizontal strategy on column heads; order is the team's, not chronological
a11y
both wrap in DndContext with announcements; a ⋯ menu offers “Move up / Move down” as the non-drag equivalent
The grid drag is the only bespoke gesture in the app — worth building once, carefully. Everything else is Sortable with a handle.
8cConcurrency & write contract — where 409 and 412 surface
412
Absence changed under you. Send modified_at with every absence write. On 412: roll the optimistic cell back, then show the inline yours/theirs banner (1b) with Keep theirs / Reapply mine. Never a spinner, never a silent refetch.
409
Project locked by another editor. Only on “Update project(s)”. Per-project and non-atomic — render one result row per project (1d), successes stay successful, the locked one gets Retry this one.
write
Team edits take no lock — there is no Request Edit Mode on any team view. Locks belong to projects only.
derive
Capacity is never stored: half-days → minus absences → minus meetings → × focus → ÷ 8 (the team's normal_day_hours, never the member's h/day) → PD → × project share × conversion → pts. Sprint Available is written only by an explicit push.
recompute
Editing a working-days version dated in the past changes open PIs only; closed PIs keep their pushed numbers until someone pushes again.
These three rules decide more of the UI than any layout choice — they are why the badge, the banner and the per-project result list exist.
